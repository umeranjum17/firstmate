# Verify firstmate-addons

## Feature map

- Lavish publication refusal (secondmate notes and merge-card posts only): run `bash owner-rules/tests/no-lavish.test.sh`; the executable checker and note hook refuse Lavish and accept sign-off links, and the real sign-off writer receives only the clean card on an isolated board.
  Set `FM_TEST_FORK=<Firstmate checkout>` to also prove the real secondmate helper writes no refused status line; raw status appends, report files and commands are outside this check.
  Capture the real publishing commands with `FM_PROOF_FORK=<Firstmate checkout> done-done run owner-rules-publication`; this records the actual refusals, absent status, unchanged board, and clean sign-off posts.
- [Pipeline route switch](features/pipeline-route-switch.md): run `bash pipeline-quota-failover/tests/switch-route.test.sh`; it uses a fixture config and a stub pi, proves that a switch edits only the agent and model keys, writes a backup first and restores it, and never touches a real config or model.
- [Incremental fleet-pulse chat export](features/incremental-fleet-pulse-chat-export.md): run `bash fleet-pulse/tests/chat-tsv.test.sh`; it uses synthetic transcripts and a disposable Git home, proves append/idempotence and redaction, and never reads real transcripts.
- Receipt hooks across the fork boundary: with a full Firstmate checkout on disk and compatible `tasks-axi` on `PATH`, run `FM_TEST_FORK=<checkout> bash receipts/tests/receipts-hook-e2e.sh`; it clones the real fork scripts and proves done acceptance, local delivery, both PR-merge call sites, the PR candidate hook (outside-origin prints PR_HEAD, same-repo and unverified print nothing) through the real `bin/fm-pr-check.sh`, and absent-add-on no-op behavior; `done-done run receipts-pr-candidate` runs it and keeps the transcript.
- Usage-limit menu move: run `done-done run limit-prompt-move` (`bash limit-prompt-move/tests/limit-prompt-move-e2e.sh`) on the real captured menu. Live: in a tmux `fm-live-lab.sh up --harness claude --mate` lab on an account at 0% week, the Haiku mate lands on the menu; with a lab-only `config/account-pool`, one `limit-prompt-move <lab home>` must interrupt and relaunch it onto the pick and leave the unrecorded primary on its menu. Never press a menu key.
- [Quota failover screen matching](features/quota-failover-screen-match.md): run `bash quota-failover/run-proof.sh`; it invokes the real failover against wrapper text and Claude's own limit banner in a disposable fixture home.
- [Quota failover pre-limit account move](features/quota-failover-prelimit.md): run `bash quota-failover/tests/quota-failover-e2e.sh`; passes 11 to 13 prove an idle working worker leaves an account at or below 15% once, while busy workers, healthy accounts and stale readings stay and Codex only wakes the home.
- Quota failover Claude tests on the pool: run `bash quota-failover/tests/quota-failover-e2e.sh`; passes 14 and 15 prove a Claude route test that names no account runs on the pool's pick (or its last good pick when the pick fails) and never on the default login.
- [Quota failover limit handoff](features/quota-failover-limit-handoff.md): run `bash quota-failover/tests/quota-failover-e2e.sh` (passes 3 and 8); for a live check, a guarded `/tmp` lab worker on a low account stops on the usage limit, one quota-failover pass moves it to another account in the same worktree, and it continues the same work.
- [Persisted pipeline route](features/pipeline-route.md): run `bash pipeline-quota-failover/tests/pi-quota-failover-route.test.sh`; it uses a stub pi and quota-axi in a throwaway HOME, proves the chain is the route the config holds and that an `openrouter/*` route keeps the deepseek idle limit, and never calls a real pi or reads a real config.
- [Fleet dashboard live core](features/fleet-dashboard-live-core.md): run `done-done run core` (`bash fleet-dashboard/run-core-proof.sh`); it seeds a throwaway Firstmate home, serves this checkout's dashboard, and captures the lanes on the Board, the Stuck and Waiting tabs, the lane cap beside a home's count, the queue reasons on Insights and the Tickets board (backlog mapping, the ask list as Waiting on captain, release lanes and the release filter), the Metrics stage rail opening a stage-filtered Board, a failing flow reader's error on Insights, and the ticket comment thread (the owner's board token, delivery to Main and to a lead through fm-send, each pickup and answer) in headless Chrome at 390px and 1280px.
- Fleet flow reader: run `FM_BIN=<Firstmate bin/> FM_ADDONS_DIR=<this checkout> bash fleet-flow/tests/fm-flow.test.sh` for the isolated two-home journey. On a live home, time `FM_HOME=<home> fleet-flow/bin/fm-flow.sh --json --capacity` read-only: it must finish inside the dashboard's 180 s probe deadline, and its status-line fields must stay byte-identical to the fork library's command-substitution forms (compare both loops over every `state/*.status` line).
- [Claude accounts quota view](features/claude-accounts-quota.md): run `bash claude-accounts/tests/claude-accounts.test.sh`; it uses a fixture muxr registry and a stub quota-axi, proves 5h and 7d left per account and a recorded failure cause, and never opens a login folder; the dashboard suite proves each account's worker count on the card.
- [Claude account first-run check](features/claude-accounts-first-run.md): in a guarded `/tmp` lab, ask one headless turn and relaunch a Haiku worker onto the account with `--account <id>`, record every screen until it replies, and report any trust, consent, login or import prompt without answering it.
- [Relaunch onto the next pool account](features/account-next-relaunch.md): run `bash account-pool/tests/account-pool.test.sh`; its fake fm-control and fm-spawn carry the `argv`, `control-validate`, `relaunch-pre`, `relaunch-commit`, `spawn-args`, `spawn-validate` and `spawn-pick` hook lines, and `relaunch --account next` must rest the recorded account once and launch on the next one with only `env -u` credential names and its folder, while every refusal touches nothing. Then, in a guarded `/tmp` lab, move a Haiku worker with `relaunch --account next` off a low account, then read its live launch: the new `pa_` account's folder and no API key or token, so no move can spend extra credits.
- [Claude accounts chooser](features/claude-accounts-pick.md): run `bash claude-accounts/tests/claude-accounts-pick.test.sh`; it uses a fixture registry and stub quota-axi, proves proportional consecutive and concurrent assignments within each provider, counter expiry, the switch when one account runs low, and install/uninstall of config/account-pool.
- [Claude accounts refresh timer](features/claude-accounts-timer.md): run `bash claude-accounts/tests/claude-accounts-timer.test.sh`; it installs the units into a throwaway tree with a stub systemctl, proves dry run, rerun and uninstall, and never touches the host's timers.
- [Merge evidence one card per PR](features/merge-card-one-card-per-pr.md): run `bash merge-card/tests/merge-card-e2e.sh`; it uses a fixture board and stub sign-off-axi, proves a new head leaves one live card and archives the old one (posted one at a time, never `--replace`), two PRs keep two cards, and the internal-change title names repo and PR. Also run `bash merge-card/tests/real-board.test.sh` for the same journey with the real sign-off-axi on a seeded temp board, plus another filer's cards for the same PR: the post and `merge-card/one-card-per-pr` keep the newest valid proof live and archive the rest.
- [Legacy merge-card retitle](features/merge-card-retitle.md): run `bash merge-card/tests/retitle-old-cards.test.sh` for the stubbed regression, then `done-done run merge-card-retitle` for the seeded fixture journey through the real sign-off-axi; together they prove dry-run safety, link and key mapping, skipping, evidence retention, archival, and idempotence.
- Merge-gate lint pin: run `bash merge-on-green/tests/checks-lint-parity.test.sh`; it uses a fake gh and isolated homes, runs the pinned done-done-axi lint against size fixtures (plain, generated, routes, oversized) and proves its PASS/FAIL verdicts match the legacy lint.
- Fleet contract check: run `done-done run fleet-contract-check` (`bash fleet-contract-check/run-proof.sh`); it runs the real script on the installed fork in a throwaway HOME (one ok or FAIL line per caller) and then the fixture journey that breaks a caller and must name it.
- Owner ask quality: run `bash ask-default/tests-owner-ask.test.sh` for the real isolated sign-off board journey (owner-only classes, plain wording, context, distinct choices, install and removal).
Run the sign-off hold journey below to prove raw backlog titles never become cards.
For authorized live cleanup, open a done-done run, use `chrome-devtools-axi` to capture the same Decide board before/after supported `sign-off-axi` commands, inspect both shots, and retain the per-card reasons; never synthesize an owner answer.
- Sign-off hold card: run `FM_CODE_ROOT=<Firstmate checkout> bash signoff/tests/fm-procevent-signoff.test.sh`; it uses a stub sign-off-axi that rejects a raise without `--ask-ref` (the real VALIDATION_ERROR), proves a hold raises its card with the hold task id as ask reference, and never touches a real board.
- Task priority check: run `bash task-priority/tests/task-priority.test.sh`; it installs the check into a throwaway `XDG_DATA_HOME`, proves a task add without `--priority 0-3` is refused naming the flag, that a priority passes with release `later`, and that an explicit `release:` line is kept.

- Pool accounts for tools: run `done-done run pool-tool-account` (`bash account-pool/run-tool-proof.sh`); a fixture pool selects Umer, the installed done-done judge backend spawns a stub Claude, and its recorded `CLAUDE_CONFIG_DIR` must equal the pick. No login or model call. Also run `bash merge-card/tests/merge-card-e2e.sh` for cached-pick fallback with age, a loud failure without cache, and no ambient judge launch.

- Guard hooks on pool accounts: run `bash kill-guard/tests/kill-guard.test.sh`, `bash read-guard/tests/read-guard.test.sh` and `bash delete-guard/tests/delete-guard-uninstall.test.sh`; each installs into a throwaway HOME with a fixture account registry and proves the Claude hook lands in the pool account folder's `settings.json` (other keys kept) and uninstall removes it. After a live install from main, a fresh `claude -p --model claude-haiku-5-5` with `CLAUDE_CONFIG_DIR=<pool folder>` asked to `cat` a planted fixture under a `.codex/auth.json` path must be refused.
- Kill guard device ownership: run `bash kill-guard/tests/kill-guard.test.sh`; its fake adb joins shell arguments the way the real one does, and `own start` must record a running process whose kill the guard then allows. On the real test phone, run one journey under `fm-device-lock.sh <serial>`: `own start <serial> -- sleep 120` returns at once and records it, the guard allows `adb -s <serial> shell kill <pid>` and refuses device PID 1 and `pkill`, and the process is gone after the kill.
- Codex guard boundary: run `bash codex-guard/tests/codex-guard.test.sh`; it installs the real delete, kill and read guards and this adapter into a throwaway HOME, runs commands the way Codex 0.159 does (snapshot wrapper, then `exec bash -c`), and proves blocks for a home delete, `kill -0 1` and a planted auth fixture, a logged delete row with runtime codex, an allowed kill of the test's own worktree process, and byte-exact uninstall.
  For the real product run `done-done run codex-guard-live` (`bash codex-guard/run-proof.sh`): it installs this checkout's guards and adapter into a temporary data folder and has the installed `codex exec`, in the crewmate shape (`--disable hooks`, so embedded), run a home delete, a planted pipeline-config read, `kill -0 1` and a kill of its own timer with a fixture HOME; it passes when the three blocks show, the delete row with runtime codex makes the watcher check wake, and the own kill runs. One short Codex turn on the signed-in account. Codex itself refuses a plain `rm -rf`, so the delete case uses `find -delete`.

## Procedure

Run the feature's integration journey from the repository root and save its output under done-done's run evidence directory.

## Safety

Use synthetic transcript fixtures only. Never use a real home or transcript directory for this proof.
