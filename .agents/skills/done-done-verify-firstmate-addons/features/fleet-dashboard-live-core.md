# Fleet dashboard live core journey

## User outcome

The fleet dashboard shows live fleet state in a real browser at a 390px phone width: each lane with its task title and state on the Board, and the queue and wait reasons on Insights. The one-tap Stuck and Waiting tabs (`#/board?tab=stuck`, `tab=waiting`) hold only those lanes, and a home's count reads against its lane cap (`4 / 3`, amber when over) in the by-home view (`rows=home`), at 390px and 1280px. Tickets (`#/tickets`) puts every backlog item on a board, To do, In progress, In review, Done and On hold, each card with its P0-P3 priority chip, target release, owner home and pull request, and only the ask list under Waiting on captain; a phone opens on that column, one column at a time. A card opens its ticket page (`#/tickets?ticket=<home>/<task>`): the description without hold bookkeeping or Main message ids, the captain's words it serves with their day, priority, release, owner, pull request, last update, and the lane's status lines as Activity.

## Drive

Run `done-done run core` from the repo root (it runs `bash fleet-dashboard/run-core-proof.sh` and sets `DONE_DONE_EVIDENCE_ROOT`). The script seeds a throwaway Firstmate home with agent lanes, in-flight, queued and held tasks and one landed task, builds and serves `fleet-dashboard/fm-dashboard.sh` from this checkout against that seed, opens the Board and Insights in headless Chrome with `chrome-devtools-axi`, and fails unless the expected lanes and reasons are on the page. It reads only the seed: stubs replace herdr, quota, device and service probes, and the queue reasons come from this checkout's fleet-flow reader. It needs a Firstmate `bin/` (`FM_BIN`, default `~/firstmate/bin`) for the dashboard's helper scripts.

## Evidence

`board-390.png` and `board.txt` show the Board lanes with their titles and states (Blocked, Main decides, waiting). `queue-390.png` and `queue.txt` show Insights with the queue and wait reasons ("Why work waits now", "Blocked · own note", "Lead reply", "Held"). Check that every lane named in the Board is one the seed wrote, and that no page text shows a raw path, id or internal word. `board-{active,stuck,waiting,homes}-{390,1280}.png` and `.txt` show the tabs and the cap; the run fails unless the Stuck tab lacks `m-build`, the Waiting tab lacks `m-stuck`, and both by-home views read `4 / 3`. `tickets-390.png`, `tickets-progress-390.png`, `tickets-1280.png` and `tickets-dark-{390,1280}.png` show Tickets in both themes; the run fails unless `board.json` maps the seeded items to their columns, priority, release and project, puts the captain-held item On hold, strips the `[captain-ask]` tag and Main ref from the name while marking it asked, and leaves Waiting on captain to the one seeded ask. `ticket-page-{390,1280}.png` and `ticket-page-dark-{390,1280}.png` show the ticket page; the run fails unless `m-ask` carries the seeded ask words with `22 Oct` and the description `Two layouts are drawn; the lead picks one.`, and the page shows them with its activity. `overview-{390,1280}.png` show Overview with a `Source:` footnote under the key figures and every card (the run fails unless the ask list, lane records, backlog archive and quota sources appear, with no raw path); `end-{overview,insights,tickets}-390.png` show each page scrolled to its end, clear of the floating tab bar. The run also fails if any link, dock button or palette entry still leads to the removed Ship tab, at 390px and 1280px. The comment journey: `POST /comment` with no or a wrong token answers 401 and an unknown ticket 404; on the ticket page a comment asks for the device token once, `ticket-comment-sent-390.png` shows it sent, the seed home's `fm-inbox.sh list` holds it, and after a build `ticket-thread-{390,1280}.png` show it in the thread as sent to Main. Do not use a real fleet home as the proof.
